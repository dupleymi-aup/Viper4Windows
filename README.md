# Viper4Windows

`Viper4Windows` — десктопное приложение для Windows для управления аудиостеком `ViPER` через современный интерфейс.

**Взаимодействие с аудиостеком:**

- через `APO/драйвер` с общей памятью
- через мост `ViPERDSP.dll` (подмодуль ViPERDSP)

**Текущий статус:** альфа‑тестирование

## Работает стабильно

- нативная оболочка на `Wails`
- установка/отключение `APO` для аудиоконечных точек
- синхронизация через общую память с `ViPER APO`
- прямая загрузка `ViPERDSP.dll`
- сохранение DSP‑состояния и пресетов в `JSON`
- управление состоянием во фронтенде
- тесты бэкенда для DSP и диспетчеризации

## В работе

- доработка интерфейса и визуальной согласованности
- паритет управления через общую память и `DLL`
- упаковка приложения и настройка первого запуска
- тестирование на разных аудиоустройствах и конфигурациях Windows

# Возможности

## Базовое управление DSP

- вкл/выкл, предварительная и постобработка громкости
- 18‑полосный эквалайзер с синхронизацией состояния
- панорама выхода и лимитеры
- сохранение и загрузка пресетов

## Модули ViPER

XBass, XBass Mono, XClarity, 3D Surround / VHE, Reverb, Convolver, DDC, AGC / Playback Gain, Dynamic System, Spectrum Extension, Field Surround, Diff Surround, Cure, Tube Simulator, AnalogX, FET Compressor, Speaker Correction

## Интеграция с драйвером

- определение наличия APO
- подключение APO к выбранной конечной точке воспроизведения/захвата
- подключение к конечной точке по умолчанию
- удаление APO с устройства
- перезапуск аудиодвижка Windows после установки/удаления

# Разработка

## Требования

- Go
- Wails CLI
- Bun
- Visual Studio Build Tools или Visual Studio с MSVC
- CMake

## Установка зависимостей фронтенда

```bash
cd frontend
bun install
```

## Запуск в режиме разработки

```bash
cd ..
wails dev
```

## Сборка DLL для DSP

```powershell
cmake --build .\ViPERDSP --config Debug
```

Для локальной разработки с `wails dev` файл `ViPERDSP.dll` должен находиться рядом со сгенерированным исполняемым файлом.

**Практичное расположение в репозитории:**

```text
build/bin/ViPERDSP.dll
```

Бэкенд загружает `DLL` из директории с исполняемым файлом при старте.

## Структура проекта

```text
Viper4Windows/
├── frontend/                # Интерфейс на Astro + React
├── ViPERDSP/                # Подмодуль DSP‑движка
├── build/                   # Результаты сборки Wails
├── app.go                   # Состояние приложения и методы бэкенда
├── driveManager.go          # Вспомогательные средства для работы с драйвером/APO
├── dspmanager.go            # Управление DSP через общую память и прямую загрузку DLL
├── dsp_core.go              # Базовая модель и типы для DSP
├── main.go                  # Точка входа Wails
└── wails.json               # Конфигурация Wails
```

## Примечания

- **Поддерживаются оба пути:** к установленному `APO` и к прямой `DLL`
- Прямой путь через `DLL` зависит от экспортируемых функций моста из подмодуля `ViPERDSP`
- Путь через `APO` и общую память — самый простой способ тестировать работу с уже установленной конфигурацией драйвера
